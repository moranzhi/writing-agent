# 叙事指南

## meta

```meta
name: 叙事指南
id: narrative-guide
artifact: 设计.叙事指南
declaration: >
  从文风库选取本局写法，落成可执行的遣词要求、笔墨落点、少量禁忌与可选写法档；不钉故事怎么往前。
when: |
  已有美学纲领（或等价），但游玩正文仍不知道怎么写：遣词什么要求、笔墨落谁身上、场合是否要换写法档、有哪些绝对不能写。
  用户主动谈文风、措辞、写法档时也使用。
when_not: |
  本技能只给对话落盘。工序编排不排本步（编排池是「叙事指南与故事推进」）。
  美学未钉 → 先「美学纲领与交互范式」。
  用户明确说本局不用文风细则，且美学里已有可执行遣词方向 → 可不使用。
  只谈推进、输入用法 → 「故事推进」。版式 → 「正文组成」。字数与可见区域 → 「回复呈现」。
boundary: |
  本能力只交怎么写：选用文风、遣词要求、笔墨落点、少量绝对禁忌、可选写法档。
  推进与输入用法归故事推进；体验契约归美学纲领。
feeds: narrator,gm
```

## opening

```opening
说说这局正文希望读起来像什么。可以直接点文风方向，或说不同场合要不要换一种写法。重点写“要怎么写”，只有真正碰不得的再提禁忌。
```

## task

```task
把本局写法整理为叙事指南，写入 `设计.叙事指南`。先用 `read_library_entry` 从绑定的文风库读取最相关条目（默认 1～2；确需第三种时须写 reason 并标明适用场合），再按本局体验本局化，写成可执行的风格推荐与要求。

产物回答：选了哪些文风、各自用在什么场合；遣词与笔墨要怎么做；只有少数绝对禁忌。除禁忌外，少写“不要怎样”，多写“要怎样”。不写示范段落，不写推进与输入用法。

材料足够便直接成稿；真正会改写法的缺口交给 `self_score.gap`。产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 文风库是参考，不是照抄：读取后改成本局可执行要求，并记下适用场合与微调。
2. 优先 1～2 种文风；确需第三种时，每种都必须有清晰切换场合，禁止无差别堆叠。
3. 写法用“风格推荐 + 要求”表达：对象、节奏、注意力落点、句段形态都写成要做什么。示范段落不写。
4. 绝对禁忌只留真正碰不得的少数几条；其余偏好都改成正向做法。
5. 写法档是多文风/多调性容器：有切换才写，无切换整项省略。场合名要能指导何时切入，不是具体剧情桥段清单。
6. 不写故事推进、输入用法、字数区间或版式壳。
```

硬规则：
1. 输出合法 JSON；`选用文风` 默认 1～2 项，最多 3 项，每项必须有适用场合与本局要求。
2. 不写示范段落、示例正文或仿写样章。
3. 除 `禁忌` 外，正文以正向要求为主；空话氛围词改成可执行做法。
4. `写法档` 无切换时整项省略；有则每档写清场合与写法要求。
5. 不在产物正文写自评、追问、开放问题或推进/输入用法。
6. `mount` 固定包含 `narrator` 与 `world-simulator`。

## score

```score
遣词可执行：
- 5：风格推荐与要求具体到能直接落笔，无需再猜味道。
- 3：大方向清楚，但仍有几处停留在氛围概括。
- 1：只有题材或情绪标签，无法指导遣词。

笔墨与禁忌：
- 5：详略落点清楚；绝对禁忌少而可执行；其余多为正向要求。
- 3：落点大体有，但禁忌偏多或详略仍含糊。
- 1：几乎不谈笔墨，或堆满否定句却无正向做法。

文风选用：
- 5：1～2（偶发 3）条贴合本局；多档时切换场合清楚，无重复堆叠。
- 3：选用相关，但场合区分弱，或有一条不够贴。
- 1：未读库硬编，或多种文风无差别并列。

本局化：
- 5：库内容已改成本局说法与要求，能看出针对本局体验的取舍。
- 3：有微调，但仍有整段近乎原文搬用。
- 1：基本照抄库条目，或与本局体验脱节。
```
