# 回复呈现

> 技能文档。程序只切割下方 **fence 块**；`##` 标题仅供人读。  
> 产物外壳：`docs/context-fragment-design.md`。  
> 旧称：设计监控栏 / 设计状态栏。  
> 本步钉：**每轮终稿有哪些区域（必选/可选）**，以及各区域的**简单内容规则**；不排版、不选壳。

```meta
when_not: |
  上游还没齐 → 先那些。
  只谈怎么排版、选壳、CSS/HTML/JS → 「正文组成」。
  只谈文风遣词 → 「叙事指南与故事推进」。
  检定/掷骰范围汇总 → 「随机范围整理」。
  变量如何增减 → 「变量设计与更新规则」（本步只定展示哪些、展示规则）。
boundary: >
  本技能：区域清单（必选/可选）+ 各区域简单内容规则（字数、自然段、选项槽位与提示口径等）。
  正文组成：如何把这些区域展示给用户（壳、美化、CSS/HTML/JS）——本步不定版式。
  随机范围整理：隐藏备用随机数表——本步不收范围。
  变量设计：真值与更新——本步可点名要展示的键与监控规则，不写增减公式。
feeds: narrator
```

## opening

```opening
每轮最终回复要分哪些区域？（想到什么写什么）

1. 必选：正文——字数、段落形态？未提及时默认：约 1000～2000 字；完整长自然段，不要单句成段。
2. 要不要状态/变量监控（如开头日期、好感）？盯哪些键？
3. 要不要选项栏？若要：几个槽、各自什么气质（如 A 冒险 / B 稳重），生成选项时遵守什么提示？
4. 要不要可选块：小故事旁支、线索条等？没有就说没有。
```

## task

```task
你正在执行「回复呈现」。产物必须是 **context-fragment.v1** JSON，写入「设计.监控栏」。

本步做两件事：
1. **区域**：每轮终稿有哪些块——哪些必选、哪些可选。
2. **简单规则**：每个启用区域怎么生成/填写（字数、自然段、选项槽与提示口径、监控键等）。

不选壳、不写 CSS/HTML/JS、不排版。展示交给「正文组成」。

默认必选：`正文`。用户未点名正文规格时，采用默认规则：
- 字数约 **1000～2000**；
- **完整长自然段叙述，不要单句成段**。
用户另有要求则以用户为准。

常见可选：`状态监控`（日期、变量芯片等）、`选项栏`、`小故事`（旁支短文）等——按体验增减，不要堆满。

执行顺序：
1. 读美学/叙事/变量/舞台：继承体验与已有真值名。
2. 钉必选区域：至少含正文；写清内容规则。未提及时用默认（1000～2000 字；长自然段、勿单句成段）。
3. 逐个判定可选区域：要则写规则；不要则不进清单（可在「刻意不启用」说明）。
4. 若开选项栏：钉槽位数、各槽气质/组成规则、生成时的短提示口径（供转述遵守）。
5. 若开状态监控：点名键、形态、刷新意图；不写变量增减公式。
6. 自评 + 追问；输出 JSON。

summary：`回复呈现 · …`（点题必选+主要可选）。
```

## principles

```principles
1. 区域 = 用户每轮会看见的内容槽；规则 = 槽里怎么写。两者都在本步钉死。
2. 正文默认必选。其它区域默认可选：有体验需要才开。
3. 规则要可执行、宜短：字数、自然段、选项槽气质、监控键名——够转述与正文组成接上即可。
   正文规格用户未提及时：字数 1000～2000；完整长自然段，不要单句成段。
4. 选项栏的「选项由什么组成 / 各槽提示词」在本步规定，不推到叙事指南或正文组成。
5. 不问「长什么样」。壳、分区、CSS/HTML/JS 交给「正文组成」。
6. 展示用的变量是子集；增减仍归变量设计。
```

## probe

```probe
每轮 1～2 点：必选是否只剩正文；某可选区开了却没规则；选项槽气质是否空；正文段落/字数是否离谱。
不追问：选哪个壳、CSS、文风遣词、变量更新公式。
```

## examples

```examples
好：
- 必选正文默认 1000～2000 字、长自然段勿单句成段；可选状态监控=日期+好感；选项栏 A 冒险 / B 稳重，各有生成提示。
- 必选正文；不开选项、不开小故事；状态只盯体力。用户要求极短时字数可低于默认。

坏：
- 只写「要选项」却不定 A/B 气质与生成提示。
- 正文无字数/段落规则。
- 在本步选壳或写 CSS。
```
