## opening

```opening
先选定这局唯一的输入用法：大纲扩写、续写，或自动写入。再说清楚单轮大约写多长、扩写和续写各做什么及各占多少；上帝视角/OOC 指令准备怎么处理。
```

## task

```task
把本局推进合同写入 `设计.故事推进`。先用 `read_library_entry` 从绑定的偏好库读取最相关 1～2 条并本局化，再只选定一种用户输入用法，按该用法写清单轮目标字数、扩写定义、续写定义、两者各自篇幅预算，以及裸写（上帝视角/OOC）指令如何处理。

禁止混用两种用法或写成半套规则。固定标记怎么识别交给程序；本步只写识别之后怎么服从与落笔。不写遣词、示范段落或版式。

材料足够便直接成稿；多种用法都像、必须用户点选时，把缺口交给 `self_score.gap`。产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 全局只允许一种用户输入用法。切分依据是扩写与续写的定义，以及两者在本局的职责和篇幅预算。
2. 三种用法互斥，写入时只保留一个完整合同：
   - 大纲扩写：输入是待演成场面的大纲。扩写要把每个节拍演满，节拍上的人、事、话、结果保持不变，节拍之间补具体动作把处境写出来；续写短，且不代用户做新决定。
   - 续写：扩写只跟用户本轮已声明的行为与对话；续写为主，停在其他角色等待用户抉择处，不替用户做态度或推进性决定。
   - 自动写入：输入多为短 meta 或极简扮演；续写宜长；可按主角设定代演用户角色言行。
3. 多写“要怎样完成扩写/续写”，少写否定清单；只有会破坏该用法边界的禁点才保留。
4. OOC/上帝视角内容由程序从裸写识别；本步写处理策略：服从到什么程度、是否打断当前场面、如何与既定扩写/续写比例兼容。
5. 偏好库是参考：读取后改成本局可执行要求，不照抄。
6. 单轮篇幅在这里一次钉死：给目标字数或窄区间，并把扩写、续写的占比与字数预算对应起来；其它节点直接消费，不重复定义。
7. 不写遣词、写法档、版式或事件池公式。
```

## score

```score
唯一性与切分：
- 5：只选定一种用法；扩写/续写定义、目标字数和预算切分清楚，无第二种用法残留。
- 3：主用法明确，但仍有一处边界、占比或字数预算含糊。
- 1：混用多种用法，或扩写/续写职责无法区分。

可执行性：
- 5：按该合同可直接开玩，扩写、续写、停笔与 OOC 处理都能执行。
- 3：大方向可用，但停笔或 OOC 处理仍需猜测。
- 1：只有用法名称，没有可执行要求。

偏好本局化：
- 5：已读偏好并改成本局要求，与唯一用法咬合。
- 3：有选用，但微调不足或与用法略冲突。
- 1：未读库却声称偏好，或照抄且与本局脱节。
```
