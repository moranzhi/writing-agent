# 故事推进

> 对话落盘技能。程序只切割下方 **fence 块**；`##` 标题仅供人读。  
> 产物外壳：`docs/context-fragment-design.md`。  
> 工序编排仍用「叙事指南与故事推进」；本步只钉怎么往前与用户输入用法，不钉遣词。

```meta
when_not: |

  只改遣词、笔墨、写法档 → 「叙事指南」。
```

## opening

```opening
美学里的轮转已有方向时，请谈「故事怎么往前」（想到什么写什么）：

1. 故事往前靠什么：场面自己推、等用户决策，还是无专门推进？
2. 用户每轮输入怎么用？未提及时按体验二选一写入（可简短确认，不必当缺口追问）：
   - **大纲扩写**（写手/成稿向）：输入＝待扩写为事实的大纲；细化完全后写正文；不超出大纲未涉及的剧情，完整演绎大纲。
   - **扮演停笔**（代入扮演、等用户决策）：用户本轮行为与对话作正文开头并扩写填满；不可写用户角色未给出的其它行为/对话；不可替用户角色做决定；正文停在其他角色等用户角色回应之刻。
```

## task

```task
你正在执行「故事推进」。产物必须是 **context-fragment.v1** JSON，写入「设计.故事推进」。

钉清本局故事怎么往前、用户每轮输入怎么用。作用对象是主世界层与转述的游玩正文。

执行顺序：
1. 继承美学/交互范式里的轮转（何时等用户），改写成推进做法。
2. 写推进与决策（可写「无专门推进」）；变量只写钩子。
   「用户输入用法」未提及时：按美学/交互范式选一种写入产物——
   - 写手/大纲成稿 → **大纲扩写**（输入＝大纲→细化成正文；不越界、完整演绎）；
   - 代入扮演、轮转等用户决策 → **扮演停笔**（输入的行为与对话作正文开头并扩写填满；不写用户角色未给出的行为/对话；不替用户角色做决定；停在其他角色等回应之刻）。
   两种都像则写进追问让用户点一次；不要混成半套规则。
3. 自评 + 追问。遣词、笔墨、写法档交给「叙事指南」，本步不写。

summary：`故事推进 · …`
```

## principles

```principles
1. 推进可轻可无；表规格交给变量/生成规则。
2. 用户输入用法两套可选默认（未提及时择一，勿混用）：
   - 大纲扩写：输入＝大纲→扩写为事实→细化后正文；不发明大纲未涉及的剧情，完整演绎大纲。
   - 扮演停笔：用户本轮行为与对话→正文开头并扩写填满；禁止描述用户角色未输入的其它行为/对话；禁止替用户角色做决定；正文停在其他角色需要用户角色回应之刻。
3. 交互范式已有停笔权限时：把它收成上面两种之一写入产物，不要因为权限已有就不落本步。
```

## probe

```probe
本步只钉两件：推进方式（场面推进 / 用户决策 / 无专门推进）、用户输入用法（大纲扩写 / 扮演停笔）。

用户未提输入用法时：按体验选一种写入产物并简短确认；两者都像才追问二选一，不必当成大缺口。
推进方式不明则正文写「无专门推进」，不问好感公式、进度表或事件池。

缺其中一件：在产物「追问」写 1～2 点。两件够验收：`追问.题目` 为 `[]`。

用户谈到遣词、笔墨、写法档：写入「开放问题」，交给「叙事指南」。
用户谈到变量增减、生成规则：只抽取能改推进方式的一句，其余写入「开放问题」。
```

