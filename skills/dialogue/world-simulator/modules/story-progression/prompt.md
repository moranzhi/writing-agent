## opening

```opening
先选定这局唯一的输入用法：大纲扩写、续写，或自动写入。再说清楚单轮大约写多长；扩写（主路径不动，在用户已给的节拍之间补连接小动作，把场面写顺）和续写（从材料结束后往下写他人与世界反应）各做什么、各占多少。上帝视角/OOC 指令准备怎么处理。故事要不要专门往前推、用户会不会失败，也可以一并说；没想过就按体验先定。
```

## task

```task
把本局推进合同写入 `设计.故事推进`。先继承上游「美学纲领与交互范式」：把 `交互范式.描写权限`（思考与抉择、言语、主动行动、用户输入后）、`后果与叙事控制` 与 `停笔时机` 改写成推进做法；交互范式已写过停笔权限，也要落进本步的用法与续写要求，不因已有而省略。再用 `read_library_entry` 从绑定的偏好库读取最相关 1～2 条并本局化，然后钉推进方式（不明则写「无专门推进」），只选定一种用户输入用法。

扩写与续写是每一轮正文里的两段工作，不是两种输入用法。按所选用法写清单轮目标字数、扩写做什么、续写做什么、两者各自篇幅预算，以及裸写（上帝视角/OOC）指令如何处理。

禁止混用两种用法或写成半套规则。固定标记怎么识别交给程序；本步只写识别之后怎么服从与落笔。不写遣词、段落形态、示范段落或版式。

材料足够便直接成稿；多种用法都像、必须用户点选时，把缺口交给 `self_score.gap`。产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. `用户输入用法` 与「扩写 / 续写」不是同一层。用法是本局选哪一种合同（三选一）；扩写、续写是每一轮正文里先后做的两段工作。产物必须先按所选用法写清这两段各自做什么，再分配篇幅。
2. 扩写：主路径不动，把用户本轮已经给出的材料演成流畅场面。人、事、话、结果保持不变；允许在节拍之间增加使动作接得上的小动作、感官和当场小纠正。只加形容词、比喻或气氛、不增加这些连接动作，不算扩写。另起新冲突、新目标、新决定，或改掉已定结果，算出界。
   例：用户写「打开冰箱门、放入大象、关闭冰箱门」——主路径就是这三步，结果仍是大象进了冰箱。只写这三句会不流畅，扩写应补门怎么拉开、大象怎么塞进去、门关不上再用力扣上等细节；不能改成没放进去、或中途改去别的房间。
   - 用法为「大纲扩写」时：材料是待演成场面的大纲，不是终稿句子。每个节拍都要演到；节拍之间必须补连接动作，大纲没写这些动作也要写。另例：大纲「我去相亲、坐了下来，她说要婚后自由出轨权，我拒绝了」——坐下前写先要一杯咖啡，又急忙改成两杯，显出局促；她的要求和拒绝的结果不动。
   - 用法为「续写」或「自动写入」时：材料是用户本轮已声明的行为与对话。扩写只在这些声明之间补过程与连接动作，可写他人怎么接这一下；不另写用户没声明的新决定。
3. 续写：从用户材料结束后往下写。写其他角色与世界如何反应、把场面推到下一个停笔点。默认不可再写用户角色的实际行动、说话或带倾向抉择；最多被动占位（望去、让开）。整轮停在其他角色等用户角色行动抉择之刻。
   - 用法为「大纲扩写」或「续写」时：禁止替用户角色做决定，不引入材料外的新剧情事实。
   - 用法为「自动写入」时：可按主角设定代演用户角色言行，把续写写长；关键抉择仍按交互范式的权限处理。
4. 三种输入用法互斥，按体验与交互范式选一种，写入时只保留一个完整合同。差别在输入是什么、扩写/续写谁长谁短、续写能不能代演用户角色：
   - 大纲扩写：用户是写手、要大纲成稿，输入多为剧情节拍时选它。扩写充分、续写短。
   - 续写（旧称扮演停笔）：代入扮演、轮转等用户决策时选它（交互范式规定关键抉择或言语只由用户做、停笔时机是等用户回应）。输入往往较短；扩写只跟已声明内容，续写多于大纲扩写、短于自动写入。
   - 自动写入：用户只给短 meta 指令或极简扮演、希望 AI 代演用户角色，且交互范式允许模型代写 user 言行（旁观、操控站位常见）时选它。扩写少、续写宜长。
5. 多写“要怎样完成扩写/续写”，少写否定清单；只有会破坏该用法边界的禁点才保留。
6. 推进可轻可无：`推进方式` 写「场面自推 / 等用户决策 / 无专门推进」之一，不明则写「无专门推进」。不自己发明好感公式、进度表或事件池；表规格交给「变量设计与更新规则」与「生成规则」。
7. 推进子维度按需填，推进方式为「无专门推进」时可全省：
   - `驱动力`：故事靠谁、靠什么往前（NPC 主动作为、世界压力与时限、用户决策），承接交互范式的 `世界对user的影响` 与 `引入新内容`。
   - `成败与难度`：用户行动会不会失败、失败怎么写（代价落在哪、挫败场面写多重），承接 `行为后果判定` 与 `设计困境`。体验本身要顺遂碾压时写明「不设失败」以及仍保留的阻力；未写明时不默认无条件顺遂。
   - `变量钩子`：推进挂在哪些变量上，每条一句「变量名：推进如何看它」；只写钩子，不写公式、阈值或数值表。
8. OOC/上帝视角内容由程序从裸写识别；本步写处理策略：服从到什么程度、是否打断当前场面、如何与既定扩写/续写比例兼容。
9. 偏好库是参考：读取后改成本局可执行要求，不照抄。
10. 单轮篇幅在这里一次钉死：给目标字数或窄区间，并把扩写、续写的占比与字数预算对应起来；其它节点直接消费，不重复定义。段落形态归叙事指南，本步不写。
11. 不写遣词、写法档、段落形态、版式或事件池公式。
```

硬规则：
1. 输出合法 JSON；`用户输入用法` 只能是三者之一，不得并列或混装半套。
2. `扩写要求` 只写「把本轮材料演成场面」怎么做；`续写要求` 只写「材料结束后往下写」怎么做。不要把另一种输入用法的规则抄进这两项。两项占比合计 100%，字数预算与目标字数对应。
3. `推进方式` 是单个字符串；`驱动力`、`成败与难度`、`变量钩子` 可选，`变量钩子` 不写公式或数值。

5. 不重定义裸写 / `#行动#` / 引号的识别规则；只写 OOC 处理策略。
6. 不在产物正文写自评、追问、开放问题、遣词示范或段落形态。
