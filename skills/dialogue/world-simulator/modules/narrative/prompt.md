# 叙事指南与故事推进

> 技能文档。程序只切割下方 **fence 块**；`##` 标题仅供人读。  
> 产物外壳：`docs/context-fragment-design.md`；对照美学：感觉 → 本步「怎么写、故事怎么往前」。  
> **一份产物、一次询问**；转述与主世界层都挂同一份（不必为省 token 拆成两套投影）。  
> **工序编排用本步。** 对话落盘拆成「叙事指南」与「故事推进」，不要在落盘池排本步。  
> 旧称：叙事指南。

## meta

```meta
name: 叙事指南与故事推进
id: narrative
artifact: 设计.叙事指南与故事推进
declaration: >
  美学已有方向时：把感觉落成可执行的遣词、笔墨落点、禁忌与推进方式；不重做体验问卷
when: |
  已有美学纲领（或等价），但转述/主世界层仍会不知道这四件：遣词什么味道、笔墨落谁身上、绝对不能写什么、故事靠场面自己推还是等用户。
  用户主动谈文风、措辞禁忌、写法档（官能/爽文/恐怖/情色等）也排。
when_not: |
  本技能只给工序编排。对话落盘不排本步（落盘池是「叙事指南」与「故事推进」）。
  美学未钉 → 先「美学纲领与交互范式」。
  用户只要感觉/站位、不要文风细则 → 不排，沿用美学。
  版式/壳 → 「正文组成」；每轮看什么（字数/变量/日期）→ 「回复呈现」。
  事件池 schema、真值增减 → 「生成规则」/「变量设计与更新规则」。
boundary: |
  本技能：一份 context-fragment，写清怎么写 + 怎么推；不必拆技能、也不必为省 token 做精细双投影。
  美学：感觉与轮转。生成规则/变量*：合同与表。
feeds: narrator,gm
```

## opening

```opening
美学里的感觉已有方向时，请谈「正文怎么写、故事怎么往前」（想到什么写什么）：

1. 像什么文风？遣词什么味道？笔墨花在谁身上？有什么绝对不能写？
2. 故事往前靠什么：场面自己推、等用户决策，还是无专门推进？正文若有几种写法档要切换（官能 / 爽文 / 恐怖 / 情色这类），点名即可；没有就说没有。
3. 用户每轮输入怎么用？未提及时按体验三选一写入（可简短确认，不必当缺口追问）：
   - **大纲扩写**（写手/成稿向）：输入占比高＝待演成场面的大纲。节拍上的人、事、话、结果不动；节拍之间补具体动作把处境演出来。拓写宜充分；续写段宜短。
   - **续写**（代入扮演、等用户决策）：输入往往较短；拓写跟已声明内容；续写多于大纲扩写、短于自动写入。
   - **自动写入**（短指令驱动）：输入＝短需求（meta 或极简扮演）；续写宜长；可按主角设定代写用户角色。
```

## task

```task
你正在执行「叙事指南与故事推进」。产物必须是 **context-fragment.v1** JSON，写入「设计.叙事指南与故事推进」。

一次对话钉清写法与推进（可交叉追问），输出**一份**正文即可。
mount：`narrator` 与 `world-simulator` 都挂同一份全文——不要为省一点点 token 拆两套裁剪方案。

执行顺序：
1. 若提示中有【文风库 · 可选用】且用户点名/对上某包：优先按该包落成「怎么写」部分，再按本局美学微调；不要重做文风问卷。推进仍按本步规则钉。
2. 否则继承美学体验与禁忌，改写成做法向句子。
3. 写纲领、遣词（含示范）、笔墨焦点、禁忌/不偏好。
   遣词用户未提段落形态时，默认写入：完整长自然段叙述，不要单句成段（篇幅数字交给「回复呈现」）。
4. 情境备用 = 写法档（体裁/调性容器），不是具体桥段。有切换则每条写：名字=档名（如「官能小说」「网文爽文」「展示恐怖」「展示情色」），用法=该档怎么遣词、笔墨落哪、何时切进来。无切换则 `[]`。用户若报出「当众折辱」「独处一室」这类场合，升一档写进对应写法档，场合本身不单列。
5. 写推进与决策（可写「无专门推进」）；变量只写钩子。
   「用户输入用法」未提及时：按美学/交互范式选一种写入产物——
   - 写手/大纲成稿 → **大纲扩写**；
   - 代入扮演、轮转等用户决策 → **续写**；
   - 短指令/meta、希望 AI 代演用户角色 → **自动写入**。
   多种都像则写进追问让用户点一次；不要混成半套规则。产物须装载对应准则（见 principles）。
6. 自评 + 追问。

summary：`叙事指南与故事推进 · …`
```

## principles

```principles
1. 感觉 vs 做法：美学写要什么爽；本步写怎么遣词、笔墨落哪、故事怎么推。
2. 遣词与禁忌要可执行；绝对禁忌 ≠ 不偏好。
   用户未提及时：完整长自然段，不要单句成段。
3. 推进可轻可无；表规格交给变量/生成规则。
   用户输入用法三选一（未提及时择一，勿混用）。差别在输入量、拓写/续写篇幅与是否代演用户角色。

   【拓写 / 续写准则】（大纲扩写、续写 必装；自动写入不装「禁代演」）
   - 拓写（大纲扩写）：输入是待演成场面的大纲，不是终稿句子。已写明的人、事、话、结果保持不变，每个节拍都要演到。节拍之间补具体动作、物件和当场的小纠正，把场合里已有的处境演出来；大纲没写这些动作也要写。例：大纲「我去相亲、坐了下来，她说要婚后自由出轨权，我拒绝了」——坐下前写先要一杯咖啡，又急忙改成两杯，显出局促；她的要求和拒绝的结果不动。只加形容词、比喻或气氛、不增加动作，不算拓写。另起新冲突、新目标，或改掉已定结果，才算出界。
   - 拓写（续写）：只写用户本轮已声明的行为与对话；可补该动作怎么发生、他人怎么接；不另写用户没声明的新决定。
   - 续写：不可再写用户角色的实际行动/说话/带倾向抉择；最多被动占位（望去/让开）；禁止替用户角色做决定。整轮停在其他角色等用户角色行动抉择之刻。
   - 篇幅：大纲扩写→拓写充分、续写短；续写用法→续写多于大纲扩写、短于自动写入。

   - **大纲扩写**：输入＝大纲→按上列大纲拓写演成正文，节拍之间补具体动作；装载上列准则。主角设定偏好：客观为主、少性格。
   - **续写**（旧称扮演停笔）：行为与对话作拓写起点；装载上列准则；主角设定偏好同大纲扩写。
   - **自动写入**：短 meta/极简扮演→长续写；允许按主角设定代写用户角色；倾向详钉性格。
4. 情境备用是写法档：名字用「官能小说」「网文爽文」「展示恐怖」「展示情色」同级；用法写该档遣词与何时切入。无切换则空数组。
5. 工序编排保持本步一份产物；对话落盘拆成「叙事指南」与「故事推进」，不要在本步执行时再拆技能。
6. 字数区间归「回复呈现」；本步管怎么写与怎么推，不重钉字数。
```

## probe

```probe
本步只钉四件：遣词可执行、笔墨落点、绝对禁忌、推进方式（场面推进 / 用户决策 / 无专门推进）。

已在美学写清的感觉改写成做法向句子，不重问「想感受到什么」。

用户未提段落形态时：写入长自然段默认并简短确认即可。
用户未提输入用法时：按体验选「大纲扩写」「续写」或「自动写入」写入产物并简短确认；多种都像才追问点选，不必当成大缺口。

缺遣词/笔墨/禁忌/推进其中一件：在产物「追问」写 1～2 点（建议选项 + 短句示例）。四件够验收：`追问.题目` 为 `[]`。推进方式不明则正文写「无专门推进」，不问好感公式、进度表或事件池。

用户谈到变量增减、生成规则、舞台百科：只抽取能改遣词 / 禁忌 / 推进方式的一句，其余写入「开放问题」。
用户提到要换写法：收成写法档写入「情境备用」（官能 / 爽文 / 恐怖 / 情色这类），不追问具体场合怎么摆；没提则 `[]`。
字数问「回复呈现」；本步不追问字数。
```
