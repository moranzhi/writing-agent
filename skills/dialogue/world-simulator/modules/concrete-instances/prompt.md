# 具体实例

## meta

```meta
name: 具体实例
id: concrete-instances
artifact: 设计.具体实例
declaration: >
  按已有生成规则填写一条记录，单独落成一份产物。没有规则时，只留下用户点名的一条字段很少的具名内容。
when: |
  已有生成规则，要按该规则写入一条种子或开局记录时使用。每条记录单独一份产物。
  还没有规则时，只在用户明确要求留下一条字段很少的具名内容时使用。
when_not: |
  还没有规则，而对象有两份以上，或字段较多、需要先审字段和填写工作流 → 先写生成规则。
  内容不重要、游玩时现写就够 → 不落本产物。
  一张有节点和连接的结构图 → 拓扑图谱。
  规则写明创作期不预填、只在游玩期生成 → 本步不写记录。
boundary: |
  本能力只交一条记录。有规则则严格按字段、池或提示、填写工作流填写；无规则则只写用户给出的少量简单字段。
  不重议合同，不写世界百科，不改变量公式。一次写入多条时，程序按记录拆成多份产物。
feeds: gm
```

## opening

```opening
先说这条记录是谁、依哪条生成规则。没有规则、又只是用户点名的一条简单内容，直接写这一条。
```

## task

```task
写出一条具体实例，写入 `设计.具体实例#中文名`。一份产物只含一条记录。用户一次给出多条时，每条各写一份；若交来的是记录数组，程序会按条拆开。

有生成规则时：认定规则的中文名，按规则的字段、池或提示、填写工作流生成这一条；用户已写明的专名与结果只扩写不改写，未写字段从已有材料往下补满。无规则且只是一条字段很少的具名内容时：直接写用户给出的字段。

材料足够便直接成稿。缺的是合同本身时，先回到生成规则，不在这里补合同。产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 有规则：字段名、取值方式、工作流阶段与依赖都以规则为准；不增删字段，不改池。
2. 池选取按合理度选择，不是程序抽签；提示约束按那句话的范围写开。
3. 按填写工作流推进：先骨架后血肉；阶段依赖与自检能核对的，生成后要能过。
4. 一份产物一条记录。多条各自成稿，用中文名称区分。
5. 无规则只写用户点名的那一条，字段保持很少；不借机发明完整人设合同。
6. 用户已写明的专名、关系、结果保持原样，只做厚度扩写；未写字段从这些材料延伸。
7. 给人读的键和专名用中文。材料里的英文名音译成中文，不把英文原名留在字段值里。外壳的 schema、brief、mount 保持既有键。
```

## output

```output
{
  "schema": "context-fragment.v1",
  "技能": "具体实例",
  "brief": "这一条是谁、依哪条规则",
  "mount": ["world-simulator"],
  "稳变": "stable",
  "正文": {
    "规则": "所依生成规则的中文名；无规则时省略",
    "名称": "这条记录的中文名",
    "记录": {
      "字段名": "按规则字段或极简内容填写的值"
    }
  }
}
```

硬规则：
1. 输出合法 JSON。`记录` 是单个对象。`名称` 用中文，并与这条记录的主名称一致。
2. 有规则时 `记录` 的键必须来自该规则字段，不得增删。
3. 无规则时省略 `规则`，`记录` 只含用户给出的少量简单字段。
4. 字段名和专名用中文；英文专名音译为中文。
5. 不在产物正文写自评、追问、开放问题或合同草稿。
6. `mount` 固定为 `["world-simulator"]`。

## score

```score
工作流符合度：
- 5：严格按规则填写工作流推进；字段、池选取、依赖与自检都落实；无规则路径则字段简单够用且不越权发明合同。
- 3：大体按工作流，但有一处阶段跳跃、依赖未咬合，或某字段明显偏薄。
- 1：忽略工作流；乱增字段；或把用户已定内容改掉。
```
