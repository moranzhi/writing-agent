> **技能标准形范例**（其它中段技能对齐本结构）。  
> 程序只切割下方 **fence 块**（`meta` / `opening` / `task` / …）；`##` 标题仅供人读。

## opening

```opening
先用几句话抓住你要的「变造世界」和体验核心（想到什么写什么，不必整齐）：

1. 原型世界是什么？变在哪里？
   例：丧尸世界，但只有我不会被感染；现代都市，但灵异是真的；也可以只说「现代都市」，变点稍后补。

2. 你代入吗？
   · 完全代入（我就是那个人，TA 的遭遇≈我的遭遇）
   · 部分代入 / 跟着体验（有距离）
   · 操控或旁观（角色是棋子/观察对象）
   · 其它（请写明）

3. 最想反复感受到的是什么？
   一句话即可——权力、求生紧张、关系拉扯、解谜、荣耀、禁忌刺激……用你自己的词。
```

## task

```task
与用户一起钉清一份「体验契约」：给玩家什么感受、如何参与、正文如何呈现、何时等待用户。

产物必须是 **context-fragment.v1** JSON，写入 tag「设计.美学纲领与交互范式」。
业务字段全部放在「正文」内（三柱为**对象**，不要写成一段散文）；须含 schema / 技能 / brief；建议填 mount 与稳变（本步不写数字 order）。
由运行时按模型能力做 schema/tool 投递，不要再口头包一层 outputs 字符串。

一次 design-step、一场对话、一次验收。参与方式与美学内容在同一步内交叉追问，不要先交「半份交互」再开「半份美学」。
用户已答过追问：把答复写入正文三块，`追问.题目` 优先 `[]`；禁止在「交互范式」与「美学纲领」之间轮流补洞拖验收。核心体验与权限边界够用即可收。

若程序已发出默认问题：用户首答在「用户.worker答复」，开场白在「创作.能力开场白」。禁止重复同一开场；在首答基础上补洞、追问、产出。黑板「用户.需求」里已有的句子当作补充材料采纳，不代替本步引导作答。
```

## principles

```principles
1. 核心是用户想要的体验；其余询问都是为了碰到这个核心。
2. 信息不足时宁可少写，不要强行填充。
3. 做好随时修改的准备；探测时大胆，用户可以说不。
4. 完善设定时不要忘掉原本的核心体验。
5. 用户常说不清想要什么 → 展示优于提问、大胆优于保守、去道德化/常态化、具体化；负面信号同样有效。
6. 变造世界：先抓「原型 + 变在哪里」；核心体验往往来自变种，不要写成设定百科。
7. 同一设定不同用户要的东西可以完全不同（角斗士：荣耀 / 自由 / 血与酒）——找到核心与禁忌，不是补全世界观。
8. 本步是上下文片段，不是执行单元清单；禁止输出 Worker 列表或最终插入 order。
```

## probe

```probe
本步只钉三件：站位（代入 / 镜头看哪 / 爽从哪来）、核心感觉（反复感受到什么）、轮转边界（何时等用户）。

用户首句或黑板已有的直接采纳。默认问题已覆盖变造、代入、核心感觉。已答清的不重问。

缺其中一件：在产物「追问」写 1～2 点（建议选项 + 短场景）；顶层 askUser 为 null。三件够验收：`追问.题目` 为 `[]`，内容维度等其余键写「未定」或省略。

用户讲人物、舞台、规则：只抽取能改这三件的一句写入正文，其余写入「开放问题」，本步不追问细节。

用两种站位或两种感觉的短场景让用户选或改，不追问开放式「你还想要什么」。
```

硬规则（公共三段 + 本技正文）：
1. 合法 JSON；必含 `schema` / `技能` / `brief` / `正文` / `自评` / `追问`（题目可 `[]`）。
2. **公共三段**：`正文`＝产物主体；`自评`＝打分（**分数 0–10 十分制，禁止百分数**）；`追问`＝导语+题目（建议选项/示例）。禁止用散文代替这三段。
3. **正文深度**：三柱（设定逻辑 / 交互范式 / 美学纲领）为对象。柱下到「条目」为止：条目是短字段、string[]，或诊断三元组 `{结论, 依据, 完备度}` / `{已知, 待探, 完备度}`。诊断里的结论/依据/已知/待探必须是字符串。禁止把整柱写成一段 text；禁止在诊断或短字段里再套对象。
4. **本技三柱**：`设定逻辑`（变造 + 参与方式 + 内容维度 + 区域/复杂性/完备度）+ `交互范式`（前置配置/视角/权限/后果）+ `美学纲领`（体验内核 + 呈现要点）。未知省略或「未定」，禁止编造百科。
5. `mount` 建议挂主世界层+转述；**禁止**写数字 `order`。`稳变` 定稿后多为 `stable`。
6. `追问.题目` 一次宜 1～3 题；有建议选项与示例；允许「其它」。已答清的不要再问。题目只写在「追问」，askUser 为 null。
7. summary：`美学纲领与交互范式 · {brief 缩略}`。

## checklist

```checklist
- [ ] 含 schema / brief / 正文 / 自评 / 追问 三段外壳？
- [ ] 正文三柱是对象（非一段散文）？设定逻辑里诊断有结论/依据/完备度？自评有交互/美学/协调维度？
- [ ] 未写 order、未输出执行单元列表？
- [ ] brief 能点题核心体验？变造/代入/满足来源清楚或已标未定？
- [ ] 交互范式权限与美学纲领互相保护、不矛盾？
- [ ] 追问只打真正薄弱点，带建议选项？已答过则题目为空、准备验收？
- [ ] 有没有为「完整」强行填充百科或偏离用户核心？
```

## examples

```examples
好：
- brief 点题「垄断生存资源的绝对掌控感」；正文三柱为对象（设定逻辑含诊断三元组、交互范式锁权限、美学纲领写体验内核）；自评打分；追问带建议选项打薄弱点。
- 内容质感可参考「权力孤岛」类长描写，但必须落在上述 JSON 键里，不要输出 XML/自定义标签壳，也不要把三柱收成一段 text。

坏：
- 只有散文纲领，无 JSON / 无自评 / 无追问结构
- 三柱是 sections[].text 一段话，验收卡无法切开诊断与契约
- 百科式背景堆砌，无满足来源与权限边界
- 输出 workers[] 或 order 表
- 追问空洞「你想要什么体验？」无选项
```
