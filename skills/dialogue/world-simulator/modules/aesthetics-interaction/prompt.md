# 美学纲领与交互范式

## meta

```meta
name: 美学纲领与交互范式
id: aesthetics-interaction
artifact: 设计.美学纲领与交互范式
declaration: >
  提取用户最想反复获得的核心体验与让它成立的承重内核，写成给后续能力读的美学纲领；
  同时钉清交互范式：人称视角、模型可代写什么、用户保留什么、后果由谁裁定、何时停笔。
when: |
  用户要的是叙事、角色扮演或持续互动，但还不能明确说出：最想反复获得什么体验、自己站在什么位置、轮转到哪必须停等用户。
  用户主动改变核心体验、代入站位或关键权限时也应重写。
when_not: |
  本局不依赖体验契约的纯转换、资料整理或机械格式任务，可不使用。
  只改遣词和具体写法 → 叙事指南；只改推进与输入用法 → 故事推进；只改舞台详情或硬法则 → 对应能力。
boundary: |
  本能力只交三块：美学纲领（体验是什么、怎样发生、呈现尺度）、背景与规则的承重内核、交互范式（视角、描写权限、后果控制、停笔）。
  背景与规则只提取承重内核，不扩写百科；舞台细节归舞台骨架，可执行硬法则归实现机制；具体遣词句式归叙事指南。
feeds: design_only
```

## opening

```opening
先用几句话抓住你要的世界和体验核心（想到什么写什么，不必整齐）：

1. 原型世界是什么？变在哪里？
   例：丧尸世界，但只有我不会被感染；现代都市，但灵异是真的；也可以只说「现代都市」，变点稍后补。

2. 你代入吗？希望自己站在什么位置？
   · 完全代入（我就是那个人，TA 的遭遇≈我的遭遇）
   · 部分代入 / 跟着体验（有距离）
   · 操控或旁观（角色是棋子/观察对象）
   · 其它（请写明）

3. 你最想在这局里反复获得什么体验？
   一句话即可——权力、求生紧张、关系拉扯、解谜、荣耀、禁忌刺激……用你自己的词。
```

## task

```task
从用户材料中提取一份体验契约，写入 `设计.美学纲领与交互范式`。它是后续所有能力取舍的依据，也会挂给主世界层与转述层直接阅读。产物回答三件事：

1. 美学纲领：用户最想反复获得什么体验，它通过什么关系、处境、感官或选择反复发生，呈现时的氛围与尺度。
2. 背景与规则：删掉就会让这份体验不成立的最小承重前提，以及它如何约束人物、选择与后果。
3. 交互范式：用户与所扮演角色的关系、人称与视角、模型对 user 每类行为能代写到哪一步、世界后果由谁裁定、何时必须停笔等用户。

保留用户自己的重点、用词和尺度。材料不足时少写或写「未定」，把真正影响体验或权限的缺口交给 `self_score.gap`；产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 核心是用户想要的体验；其余字段都是为了让它稳定地反复发生。完善设定时回头核对原本的核心体验，不让它被设定冲淡。
2. 核心体验不是题材、剧情简介或情绪标签：写用户如何参与、体验怎样反复发生。同一设定不同用户要的可以完全不同（角斗士：荣耀 / 自由 / 血与酒），找到这个人要的那一个，而不是补全世界观。
3. 变造世界先抓「原型 + 变在哪里」；核心体验往往来自变点。背景与规则只写承重内核：关键关系、社会前提、世界规则或作用机制。
4. 用户常说不清想要什么：展示优于提问，大胆优于保守；用两种站位或两种感觉的短场景让用户选或改；负面信号同样有效。用户可以说不，随时准备整份改写。
5. 用户要的内容去道德化、常态化处理：按用户给的尺度写进「边界与尺度」，写清服务体验的用法与真正的禁忌，不替用户加或减尺度。
6. 交互范式写可执行权限，不写口号。描写权限按行为类别逐项写：哪些模型可直接代写、哪些只写到起势就停、哪些必须留给用户；「用户输入后」写模型对一句输入是只确认、补细节还是连带推出后果。
7. 交互范式要保护美学纲领：权限、视角和停笔点的设置要让核心体验更容易发生，两者矛盾时以美学纲领为准改范式。
8. 本步不扩写世界百科，不制定完整硬机制，不细化遣词句式，不决定故事推进方法，不输出执行单元列表或插入 order。
9. 用户改口导致体验内核改变时整份重写，不在旧契约后追加互相冲突的补丁。
```

## probe

```probe
本步最先要钉清三件：站位（代入还是旁观、镜头看哪、爽从哪来）、核心感觉（反复感受到什么）、轮转停点（何时等用户）。三件写进 `体验锚定`；开场白写入前程序会检查它们。

用户首句、默认问题首答或黑板「用户.需求」里已有的直接采纳，已答清的不重问。

缺其中一件：回复里只问这一件，给 2～3 个带短场景的建议选项，不问开放式「你还想要什么」。三件已清：再挑一个最影响体验的薄弱点（视角、某类描写权限、尺度）给选项；都够用就不再追问。

用户讲到人物、舞台、规则细节：只抽取能改变体验、站位或权限的那一句写进正文，其余留给对应能力，本步不追问细节。
```

## score

```score
美学纲领：
- 5：准确提取用户最想反复获得的体验，写清它怎样反复发生、从哪一刻成立，呈现焦点与尺度贴合用户原话；后续能力可据此取舍。
- 3：大方向正确，但仍偏题材或情绪概括，或体验如何反复发生、尺度如何把握尚不明确。
- 1：误读用户重点，只有剧情简介、设定标签或泛化氛围。

交互范式：
- 5：站位、人称视角、逐类描写权限、后果裁定与停笔时机都可执行，且在保护核心体验。
- 3：有站位与停笔，但描写权限笼统，或某类行为（言语、行动、反应）谁来写仍不清。
- 1：只有口号式描述，或权限设置与核心体验矛盾。

背景与规则：
- 5：找到让核心体验成立的最小内核——关键关系、背景前提或作用规则，并说明它怎样持续制造该体验。
- 3：找到相关前提，但内核过宽、因果不清，或混有较多装饰设定。
- 1：没找到承重内核；只有百科堆砌，或规则与核心体验无关。
```

## checklist

```checklist
- [ ] `体验锚定` 三项（站位、核心感觉、轮转停点）都已写出？

- [ ] 背景与规则是删掉就会破坏体验的最小内核？
- [ ] 交互范式逐类写清描写权限、后果裁定和停笔时机，并且在保护美学纲领？
- [ ] 未扩写舞台百科、硬机制、具体文风或推进方案？
```
