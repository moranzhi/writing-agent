```meta

declaration: >
  提取用户最想反复获得的核心体验，以及让它成立的背景与规则内核；同时钉清参与和停笔边界。
when: |

  背景与规则只提取承重内核，不扩写百科；舞台细节归舞台骨架，可执行硬法则归实现机制。
```

## opening

```opening
先说你最想在这局里反复获得什么体验，以及你希望自己站在什么位置。可以直接给一个场景、关系或感觉，不必先整理设定。
```

## task

```task
从用户材料中提取一份体验契约，写入 `设计.美学纲领与交互范式`。产物只回答三件事：用户最想反复获得什么核心体验；什么最小背景或规则内核让它成立；模型与用户各自能决定什么、何时必须停笔。

保留用户自己的重点和尺度。材料不足时少写，把真正影响核心体验或背景内核的缺口交给 `self_score.gap`；产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 核心体验不是题材、剧情简介或情绪标签；要写用户如何参与、体验怎样反复发生。
2. 背景与规则寻找最小承重内核：可以是关键关系、社会前提、世界规则或作用机制。删掉它会使核心体验不成立。
3. 角色人文关系、描写焦点和文风信号可作为核心体验的组成材料，但不为评分硬拆成独立维度。
4. 本步不扩写世界百科，不制定完整硬机制，不细化遣词句式，不决定故事推进方法。
5. 参与边界写可执行权限：模型可补哪些反应与行动，哪些决定必须留给用户，何时停笔。
6. 用户改口导致体验内核改变时整份重写，不在旧契约后追加互相冲突的补丁。
```

## score

```score
核心体验：
- 5：准确提取用户最想反复获得的体验，写清用户站位、体验如何发生及何时停笔；后续能力可据此取舍。
- 3：大方向正确，但仍偏题材或情绪概括，或体验如何反复发生尚不明确。
- 1：误读用户重点，只有剧情简介、设定标签或泛化氛围。

背景与规则：
- 5：找到让核心体验成立的最小内核——关键关系、背景前提或作用规则，并说明它怎样持续制造该体验。
- 3：找到相关前提，但内核过宽、因果不清，或混有较多装饰设定。
- 1：没找到承重内核；只有百科堆砌，或规则与核心体验无关。
```
