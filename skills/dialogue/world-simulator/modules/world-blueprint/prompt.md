# 舞台骨架

## meta

```meta
name: 舞台骨架
id: world-blueprint
artifact: 设计.舞台骨架
declaration: >
  保存会在游玩中反复影响世界反馈的外部舞台：熟悉基底、必要变造、核心运转和主要活动场所。
when: |
  核心体验依赖外部环境、社会力量或世界状况持续作出一致反馈，而现有材料还不足以支撑这些反馈时使用。
  是否换区不是判断标准：跨越多地可以需要舞台骨架；一室之内的朝堂、审讯或家庭关系同样可以需要。
when_not: |
  熟悉现实基底已经够用，地点和外部格局不会改变核心体验或世界反馈时不使用。
  既成硬法则归实现机制；多份人物或要先审字段的名片归生成规则，单条字段很少的具名内容才归具体实例；重点在节点与连接本身时归拓扑图谱。
boundary: |
  本能力只交会上台并反复有用的外部事实，其余沿用熟悉常识或明确留白。
  不重写核心体验，不解释硬法则起源，不制作人物名片、完整地图、历史或百科。
feeds: gm
```

## opening

```opening
说说这局里会反复影响你的外部舞台：它以什么熟悉世界为基底，哪里不同，哪些场所、关系或世界状况会持续参与反馈。只写真正会上台的部分即可。
```

## task

```task
把用户材料整理为一份可供主世界层稳定反馈的舞台骨架，写入 `设计.舞台骨架`。先确定最短的熟悉基底与必要变造，再提取会反复影响玩家的社会关系、环境条件和主要场所；体验碰不到的范围明确留白。

材料足够便直接成稿。若两种舞台尺度或运转条件会导致明显不同的世界反馈，把这一处缺口交给 `self_score.gap`；产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 舞台以世界怎样回应玩家为准，不以是否换区、地图大小或题材类型为准。
2. 熟悉常识默认继承，只写相对基底的必要变造，以及会反复参与体验的外部事实。
3. 核心运转可以是社会力量、阶层关系、周期事件、资源条件、禁忌或日常秩序；只说明它如何作用于玩家和主要舞台。
4. 主要舞台可以是空间、机构、社会层或一间房；详细度以能稳定反馈为止。
5. 既成硬法则只引用其结果，规则本身交给实现机制；多份或要先审字段的具名人物交给生成规则，单条字段很少的具名内容才交给具体实例。
6. 用户未触及的地区、历史、物种、民俗和势力不补全，在留白边界中说明即可。
```

硬规则：
1. 输出合法 JSON；未知或无内容的可选字段直接省略，不写“未定”占位。
2. `核心运转` 统一容纳必要的社会结构与世界状况，不为分类而补内容。
3. `主要舞台` 只写会反复上台且需要稳定反馈的部分；单一房间也可成为完整舞台。
4. 不在产物正文写自评、追问、开放问题、覆盖检验或设定诊断。
5. `mount` 固定为 `["world-simulator"]`。

## score

```score
支撑度：
- 5：核心体验依赖的舞台、关系和运转条件均足以支持稳定世界反馈。
- 3：方向正确，但缺少一项会反复影响体验的环境或社会条件，或其作用尚不明确。
- 1：只有题材或地点标签，无法据此判断世界如何回应玩家。

克制度：
- 5：只写会上台且反复有用的内容，熟悉常识默认继承，其余明确留白。
- 3：夹带少量暂时不会影响游玩的地图、历史或设定。
- 1：写成完整世界百科，核心舞台反而不突出。
```

## checklist

```checklist

- [ ] 核心运转只含会反复作用的关系与状况？
- [ ] 主要舞台详细度够用即止，未触及范围已留白？
- [ ] 未重写体验、硬法则、人物名片、完整历史或百科？
- [ ] 产物正文不含评分、诊断、追问和开放问题？
```
