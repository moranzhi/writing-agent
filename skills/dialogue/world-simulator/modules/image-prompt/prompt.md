# 画面与生图

## meta

```meta
name: 画面与生图
id: image-prompt
artifact: 设计.画面与生图
declaration: >
  从工作流库选定一种画面工作流，并写成旁观每轮可执行的生图提示词合同。
  游玩时不再改选工作流。
when: |
  用户要给游玩配图，或点名某种画面风格（西幻、写实、东方玄幻等）。
when_not: |
  用户没提配图、插图或画面风格。
  只改遣词 → 叙事指南。只改真值 → 变量设计与更新规则。
  壳上的背景、立绘先不做。
boundary: |
  本步只交：选中的工作流 id，以及这一局的画面提示词怎么写。
  不写 ComfyUI 节点图，不写某一轮的成品提示词，不写真值与填表规则。
  产物只挂旁观。主世界层不读。
feeds: auditor
```

## opening

```opening
这局游玩要不要配图？要的话，画面更接近库里的哪一种？人物或场面里有什么必须反复画出来？
```

## task

```task
为这本书选定一种画面工作流，并写下旁观每轮写生图提示词时要遵守的合同，写入 `设计.画面与生图`。

先看工作流库目录。用户点了名、或和本局世界明显同一种画面时，用 `read_library_entry` 读取那一条（只读 1 条）。把该条目的 id 原样写入 `工作流`。`画什么`、`始终带上`、`不画`、`写法` 按本局来写：工作流已经带上模型和画风，写法里说明提示词写场面与可见人物，不另起一套画风形容词。

库是空的，或没有对得上的条目：不要编一个 id。`工作流` 留空字符串，并在 `self_score.gap` 写明库里还没有可用工作流。

材料够就成稿。产物正文不含评分、诊断或某一轮的成品提示词。
```

## principles

```principles
1. 工作流只选库里已有的一个 id。游玩期间定死，不在合同里留备选。
2. `画什么` 写每轮从正文取哪些可见内容（场所、在场的人、刚发生的动作），一句。
3. `始终带上` 只留本局必须反复出现的外貌或标志，每条一句。没有就空数组。
4. `不画` 只留不该进画面的东西，例如界面、选项、系统字。没有就空数组。
5. `写法` 写提示词的语言、粗细，以及要不要重复画风词。不写一场示范提示词。
6. 节点图、采样器、模型文件名不写入产物。
7. `mount` 只有 `auditor`。
```


硬规则：
1. 输出合法 JSON。`工作流` 是库里的一个 id，或库空时的空字符串。
2. `mount` 只有 `auditor`。
3. 不写节点图，不写某一轮的成品提示词，不写真值。
4. 产物正文不写自评和追问。

## score

```score
工作流：
- 5：id 来自库，且和本局画面一致。
- 3：id 在库里，但和用户说的风格偏了。
- 1：库里没有却编了一个 id。

提示词合同：
- 5：画什么、始终带上、写法都能让旁观直接写下一轮提示词。
- 3：方向有了，但写法仍是氛围词，或写成了一段示范提示词。
- 1：只有风格标签，没有可执行的取景说明。
```

```checklist

```

## examples

```examples
好：
- 库有 `eastern-fantasy`，用户要仙侠 → `工作流` 写该 id。`画什么`：「这一轮正文里看得到的场所、在场的人和正在做的动作」。`写法`：「中文短句；模型已是东方玄幻，提示词不另堆画风词」。

缺料时：
- 工作流库没有任何条目 → `工作流` 为 ""，gap 写明还没有可用工作流。

偏了就改回：
- 把某一场的完整提示词写进 `写法` → 改成语言和粗细。
- `mount` 写了 world-simulator → 改成只有 auditor。
```
