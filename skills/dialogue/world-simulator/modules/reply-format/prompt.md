# 正文组成

> 技能文档。程序只切割下方 **fence 块**；`##` 标题仅供人读。  
> **创作定位：把「回复呈现」已钉的内容展示给用户**（选壳、美化排版，可写 CSS/HTML/JS）。壳介绍与规格写在各壳自己的文档，程序动态装载。  
> 产物外壳：`docs/context-fragment-design.md`。  
> 旧称：设计回复格式。

```meta
  必须在「开场白与开场变量」之前。
when_not: |
  还不知道每轮给用户看什么 → 先「回复呈现」。
  已定要检定/掷骰但范围表未收 → 先「随机范围整理」。
  不要排在开场白之后。几乎不跳过。
  只谈文风遣词 → 「叙事指南与故事推进」。只改呈现区域与内容规则（字数/选项槽/监控键）→ 「回复呈现」。
boundary: |
  本技能：前端展示——从【可选呈现壳】选壳、把回复呈现的各区域落到版式、美化排版（可含 CSS/HTML/JS）；若有随机范围表，预留/接到隐藏备用随机区（用户看不见、发给 AI 仍在上下文）。
  回复呈现：必选/可选区域 + 各区简单内容规则——本步不重议清单与规则，只负责怎么显示。
  随机范围整理：要插哪些数、范围是什么——本步不改范围表，只负责怎么藏进消息。
  叙事指南：文风。变量设计：真值规则。开场白：第一屏——本步先定展示。
feeds: narrator
```

## opening

```opening
本局把「回复呈现」里已钉的内容展示给用户（选壳、美化排版）。壳清单由程序动态装载，不要背死几种。

1. 对照【可选呈现壳】：哪一个最适合放下已钉的那些东西？
2. 各项落到壳的哪一区？显示名叫什么？
3. 要不要额外的 CSS/HTML/JS 来美化（没有就说没有）？
4. 定稿时会用前面情节架空一幕灌进壳里，专供你看版式/美化（内容随便，不当正史）。
```

## task

```task
你正在执行「正文组成」。产物必须是 **context-fragment.v1** JSON，写入「设计.正文组成」。

本步 = **前端展示**：按「回复呈现」的清单，从【可选呈现壳】里选一个，把内容落到区域并美化排版。可写本局需要的 CSS/HTML/JS。
禁止重议「看什么、正文多少字」；禁止自造目录没有的 shell_id。

执行顺序：
1. 读「回复呈现」与美学/叙事：清单是权威；不重开「看什么」问卷。
2. **选 shell_id**（必须是【可选呈现壳】里的 id）；说明为何这个壳放得下清单里的项。
3. 可见块：把清单各项挂到该壳已有区域；写显示名与职责。
4. 需要时写「渲染」：本局 CSS/HTML/JS 片段（美化排版，不是新后端协议）。
5. 隐藏段（若清单要求）：定界与用途。
6. 填「呈现壳.微调」；分区必须与壳一致。
7. **示例**：用前面已定情节架空一幕灌进 `present.v1`，专供验收版式/美化；字数以回复呈现为准，本步不重钉篇幅。
8. 自评 + 追问；禁止写 context `order`。

summary：`正文组成 · 适配 {shell_id} · …`。
```

## principles

```principles
1. 创作 = 把「回复呈现」的清单展示出来
   选壳、分区、显示名、CSS/HTML/JS 都为那份清单服务。本步验收重点是「看起来对不对」。
   「按意见修改」：以最新产物为底；用户要求按先后都有效，冲突时以较新的为准。用户说整体可以、或只提美化 → 不换 shell_id。换壳必须用户点名。

2. 清单权威在「回复呈现」
   正文篇幅、要不要日期、展示哪些变量，以那份产物为准。本步只决定怎么显示。

3. 壳是底，渲染可加
   从【可选呈现壳】选底。需要时写本局 CSS/HTML/JS 做美化；不要发明新的后端协议或目录没有的壳。

4. 隐藏段服务维护，不污染阅读

5. 与转述、变量分工
   文风归叙事指南；真值归变量设计；看什么归回复呈现；本步只交展示契约。

6. 示例 = 壳与美化预览，非正史
   用已定材料随便架空一幕，把各区域/监控/行动坞撑满，让用户看见版式。
   禁止把示例当成开场白或游玩 canon；禁止为写好看而新造设定；文笔及格即可，勿打磨成章。
```

## probe

```probe
每轮 1～2 点。

优先：壳能否放下回复呈现的各项；分区与显示名；要不要 CSS/HTML/JS。
不追问：重议字数/变量清单、事件池 schema、文风遣词、示例文笔好坏。
```

硬规则：
1. 合法 JSON；含公共三段外壳。
2. 正文须含 `呈现壳.shell_id`（须在【可选呈现壳】内）与 `微调`；可见块只挂壳已有区域。
3. `可见块` 至少 1 条（通常含 body）；禁止自造区域 id / 目录没有的壳。
4. 正文须含 `示例`：`性质` 标明非正史；`灌数` 为 `present.v1`，`shell` 与本步 shell_id 一致；只填该壳已有区域。
5. 示例内容可糙：只为验收壳与美化；禁止当开场白/正史；禁止为示例新造设定。
6. 禁止程序 API schema、context `order`。需要美化时写本局 CSS/HTML/JS，不要另起后端协议。
7. 自评：可见完备 / 清单落实 / 可实现 / 版式可感。
8. summary：`正文组成 · 适配 {shell_id} · {brief 缩略}`。
9. 兼容旧称产物 tag「设计.回复格式」。

## checklist

```checklist
- [ ] 是把「回复呈现」的清单展示出来，而不是重议看什么？
- [ ] shell_id 在【可选呈现壳】内？可见块未超出该壳分区？
- [ ] 清单各项已落到区域？字数未在本步另定一套？
- [ ] 隐藏段（若有）定界清楚？CSS/HTML/JS 只服务本局展示？
- [ ] 有示例灌数（present.v1），壳一致、各区撑开，且标明非正史？
- [ ] 未把示例写成开场白或打磨成长文？
```
