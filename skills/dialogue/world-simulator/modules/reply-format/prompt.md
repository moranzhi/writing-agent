# 正文组成

> 技能文档。程序只切割下方 **fence 块**；`##` 标题仅供人读。  
> **创作定位：基于固定呈现壳做适配微调**（`docs/play-presentation-shells.md`）。  
> 产物外壳：`docs/context-fragment-design.md`。  
> 旧称：设计回复格式。

## meta

```meta
name: 正文组成
id: reply-format
artifact: 设计.正文组成
declaration: >
  基于七种固定呈现壳做适配微调（选 shell_id + 填字段/显示名/开关等）；
  产出壳适配单；禁止从零发明布局或完整 UI
when: |
  需要为本局选定呈现壳，或微调监控字段/块显示名/建议行动开关时；
  或需要约定隐藏变量段时。
when_not: |
  明确只要纯散文 → 可不排（运行时默认 prose）。
  只谈文风 → 「叙事指南与故事推进」。
  壳已定、只筛监控字段明细 → 「设计监控栏」。
  不要在本步设计新布局或写 CSS。
boundary: |
  本技能：壳适配单（shell_id + 微调轴 + 块挂到壳已有区域）。
  布局骨架只读：docs/play-presentation-shells.md。
  设计监控栏：字段表细则。叙事指南：文风。变量设计：真值规则。
feeds: narrator
```

## opening

```opening
本局在固定呈现壳上做适配（不是设计新界面）。

0. 按「要同时看见什么」七选一：
   · prose — 只要正文
   · chat_monitor — 正文 + 扫状态
   · spotlight — 大正文 + 弱状态
   · turn_panel — 场面 + 交互物 + 行动
   · split_board — 正文 ‖ 线索
   · choice_dock — 局面 + 选项
   · chapter_reader — 章正文 + 进度

1. 要微调什么？（监控字段、块称呼、要不要建议行动、tone_chrome…）
2. 有没有隐藏段给模型/程序维护变量？
3. 定稿时会用前面情节架空一幕灌进壳里，专供你看版式/美化（内容随便，不当正史）。
4. 不要谈「再发明一种全新布局」。
```

## task

```task
你正在执行「正文组成」。产物必须是 **context-fragment.v1** JSON，写入「设计.正文组成」。

本步 = **壳适配单**：七种壳里选一个，只改允许的微调轴。
权威：`docs/play-presentation-shells.md`。
禁止从零设计分区、禁止自造 shell_id、禁止完整 CSS。

执行顺序：
1. 读美学/叙事：继承人称与终稿归属；不重开文风问卷。
2. **选 shell_id**；说明为何是这个壳而不是其它壳（主面积给谁）。
3. 可见块：只挂到该壳已有区域；写显示名与职责（适配文案，不是新分区）。
4. 监控栏：字段意图（细则可交「设计监控栏」）；无 monitor 的壳写「不启用」。
5. 隐藏段（若有）：定界与用途。
6. 填「呈现壳.微调」；前端拆分区域必须与壳一致。
7. **示例**：用前面已定情节架空一幕，按本步壳与可见块灌进 `present.v1` 形状，专供验收版式/美化；示例文可短，游玩正文字数不在本步打磨。
8. 自评 + 追问；禁止写 context `order`。

summary：`正文组成 · 适配 {shell_id} · …`。
```

## principles

```principles
1. 创作 = 选壳 + 适配微调
   不是 UI 创意；布局骨架只读。本步验收重点是「看起来对不对」，不是故事写得好不好。
   「按意见修改」：以最新产物为底；用户要求按先后都有效，冲突时以较新的为准。用户说整体可以、或只提美化/行距/显示名 → 不换 shell_id。换壳必须用户点名。

2. 只改微调轴
   字段、显示名、开关、tone_chrome、空态；不改分区、不增区域、不自造壳。

3. 监控栏 ≠ 名片卡
   只盯会变、影响决策或沉浸的信息。

4. 隐藏段服务维护，不污染阅读

5. 与转述、变量分工
   文风归叙事指南；真值归变量设计；本步只交壳适配契约。
   游玩单轮用户主读正文默认 500～2000 字，写进「拼装与终稿.单轮正文篇幅」，供转述遵守。

6. 示例 = 壳与美化预览，非正史
   用已定材料随便架空一幕，把各区域/监控/行动坞撑满，让用户看见版式。
   禁止把示例当成开场白或游玩 canon；禁止为写好看而新造设定；文笔及格即可，勿打磨成章。
```

## probe

```probe
每轮 1～2 点。

优先：选哪个壳；微调哪些字段/显示名；隐藏段要不要；示例灌数是否让版式看得清。
不追问：新布局、完整 CSS、事件池 schema、文风遣词、示例文笔好坏。
```

硬规则：
1. 合法 JSON；含公共三段外壳。
2. 正文须含 `呈现壳.shell_id`（七种之一）与 `微调`；可见块只挂壳已有区域。
3. `可见块` 至少 1 条（通常含 body）；禁止自造区域 id / 第五种壳。
4. 正文须含 `示例`：`性质` 标明非正史；`灌数` 为 `present.v1`，`shell` 与本步 shell_id 一致；只填该壳已有区域。
5. 示例内容可糙：只为验收壳与美化；禁止当开场白/正史；禁止为示例新造设定。
6. 禁止程序 API schema、context `order`、完整 CSS。
7. 自评：可见完备 / 监控克制 / 可实现 / 版式可感。
8. summary：`正文组成 · 适配 {shell_id} · {brief 缩略}`。

## checklist

```checklist
- [ ] 是「选壳+微调」，不是从零设计布局？
- [ ] shell_id 在七种壳内？可见块未超出该壳分区？
- [ ] 微调轴已填或明确默认？监控栏未塞死名片字段？
- [ ] 隐藏段（若有）定界清楚？未写 CSS 工程？
- [ ] 有示例灌数（present.v1），壳一致、各区撑开，且标明非正史？
- [ ] 未把示例写成开场白或打磨成长文？
```
