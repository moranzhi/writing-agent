# 正文组成

> 技能文档。程序只切割下方 **fence 块**；`##` 标题仅供人读。  
> **创作定位：把「回复呈现」已钉的内容展示给用户**（选壳、分区、用安全子集美化）。壳与【正文安全子集】由程序动态装载。  
> 产物外壳：`docs/context-fragment-design.md`。  
> 旧称：设计回复格式。

  本技能：前端展示——从【可选呈现壳】选壳、把回复呈现的各区域落到版式；正文语法以【正文安全子集】为准（折叠、表格等）。
  回复呈现：必选/可选区域 + 各区简单内容规则——本步不重议清单与规则，只负责怎么显示。

  叙事指南：文风。变量设计：真值规则。开场白：第一屏——本步先定展示。

## opening

```opening
本局把「回复呈现」里已钉的内容展示给用户（选壳、分区、安全子集美化）。壳与安全子集由程序动态装载，不要背死。

1. 对照【可选呈现壳】：哪一个最适合放下已钉的那些东西？
2. 各项落到壳的哪一区？显示名叫什么？渲染提示用纯文本还是 Markdown？
3. 需要折叠/表格等时，对照【正文安全子集】（一般够用；html/css/js 默认空）。
4. 定稿时会用前面情节架空一幕灌进壳里，专供你看版式/美化（内容随便，不当正史）。
```

## task

```task
你正在执行「正文组成」。产物必须是 **context-fragment.v1** JSON，写入「设计.正文组成」。

本步 = **前端展示**：按「回复呈现」的清单，从【可选呈现壳】里选一个，把内容落到区域。
正文美化优先【正文安全子集】（用户开 Markdown 渲染时生效）。日常折叠、表格等走子集即可；「渲染」里 html/css/js 默认空字符串。
禁止重议「看什么、正文多少字」；禁止自造目录没有的 shell_id；禁止发明子集没有的语法。

执行顺序：
1. 读「回复呈现」与美学/叙事：清单是权威；不重开「看什么」问卷。
2. **选 shell_id**（必须是【可选呈现壳】里的 id）；说明为何这个壳放得下清单里的项。
3. 可见块：把清单各项挂到该壳已有区域；写显示名与职责；渲染提示选「纯文本」或「Markdown」。
4. 「渲染」html/css/js：默认全空；仅当用户点名要超出安全子集的交互时再议（本步通常不写）。
5. 隐藏段（若清单要求）：定界与用途。
6. 填「呈现壳.微调」；分区必须与壳一致。
7. **示例**：用前面已定情节架空一幕灌进 `present.v1`；body 可演示子集语法（如折叠/表格）；字数以回复呈现为准。
8. 自评 + 追问；禁止写 context `order`。

summary：`正文组成 · 适配 {shell_id} · …`。
```

## principles

```principles
1. 创作 = 把「回复呈现」的清单展示出来
   选壳、分区、显示名、安全子集语法都为那份清单服务。本步验收重点是「看起来对不对」。
   「按意见修改」：以最新产物为底；用户要求按先后都有效，冲突时以较新的为准。用户说整体可以、或只提美化 → 不换 shell_id。换壳必须用户点名。

2. 清单权威在「回复呈现」
   正文篇幅、要不要日期、展示哪些变量，以那份产物为准。本步只决定怎么显示。

3. 壳是底，子集是语法
   从【可选呈现壳】选底；Markdown 区只使用【正文安全子集】。不要发明新后端协议、目录没有的壳、或子集没有的语法。

4. 隐藏段服务维护，不污染阅读

5. 与转述、变量分工
   文风归叙事指南；真值归变量设计；看什么归回复呈现；本步只交展示契约。

6. 示例 = 壳与美化预览，非正史
   用已定材料随便架空一幕，把各区域/监控/行动坞撑满，让用户看见版式。
   禁止把示例当成开场白或游玩 canon；禁止为写好看而新造设定；文笔及格即可，勿打磨成章。
```

## probe

```probe
每轮 1～2 点。

优先：壳能否放下回复呈现的各项；分区与显示名；渲染提示纯文本还是 Markdown；要不要子集里的折叠/表格。
不追问：重议字数/变量清单、事件池 schema、文风遣词、示例文笔好坏、本局任意 CSS/JS。
```

硬规则：
1. 合法 JSON；含公共三段外壳。
2. 正文须含 `呈现壳.shell_id`（须在【可选呈现壳】内）与 `微调`；可见块只挂壳已有区域。
3. `可见块` 至少 1 条（通常含 body）；禁止自造区域 id / 目录没有的壳。
4. 正文须含 `示例`：`性质` 标明非正史；`灌数` 为 `present.v1`，`shell` 与本步 shell_id 一致；只填该壳已有区域。
5. 示例内容可糙：只为验收壳与美化；禁止当开场白/正史；禁止为示例新造设定。
6. 禁止程序 API schema、context `order`。Markdown 区只使用【正文安全子集】；渲染 html/css/js 默认空。
7. 自评：可见完备 / 清单落实 / 可实现 / 版式可感。
8. summary：`正文组成 · 适配 {shell_id} · {brief 缩略}`。

## checklist

```checklist
- [ ] 是把「回复呈现」的清单展示出来，而不是重议看什么？
- [ ] shell_id 在【可选呈现壳】内？可见块未超出该壳分区？
- [ ] 清单各项已落到区域？字数未在本步另定一套？
- [ ] Markdown 区语法落在【正文安全子集】内？渲染三字段默认空？
- [ ] 有示例灌数（present.v1），壳一致、各区撑开，且标明非正史？
- [ ] 未把示例写成开场白或打磨成长文？
```
