# 正文组成

## meta

```meta
name: 正文组成
id: reply-format
artifact: 设计.正文组成
declaration: >
  把普通楼层「回复呈现」的语义区域落成每条消息使用的前端模板：
  定义区域位置、HTML/CSS/JS、数据绑定与特殊渲染。
when: |
  已有普通楼层「回复呈现」，需要决定每个语义区域在气泡内如何显示时使用。
  排在回复呈现之后、开场白与开场变量之前。
when_not: |
  还不知道回复包含哪些语义内容 → 先回复呈现。
  要设计持久 0 层卡、槽位更新或跨轮 Tab → 使用 0层正文组成，不在本节点兼顾。
boundary: |
  回复呈现决定“有什么、何时出现、来自哪里”；本能力决定“在前端哪里、如何渲染”。
  状态和拓扑数据由程序投影，本能力只写绑定与渲染器；不得让正文模型重写权威数据。
  隐藏维护区不进 DOM。随机数是变量表隐藏行，也与本能力无关。
  壳参考库只提供布局与交互方法参考，不是必须照抄的固定产品模板。
feeds: gm,narrator
```

## opening

```opening
把回复呈现里已启用的语义区域做成普通消息气泡内的前端。先决定阅读主次和区域落点，再按需设计 Tab、表格、拓扑图等渲染；隐藏维护区不显示。
```

## task

```task
为普通楼层生成一份可复用前端，写入 `设计.正文组成`。每条助手消息仍各自形成一个气泡；程序把当轮 `present.v1` 灌入同一模板。

执行顺序：
1. 读取回复呈现，只处理其中实际启用的语义区域。
2. 从【壳参考库】选一只与本局已启用区域最接近的壳。按该壳备注改写样本里的名称、栏目、配色和内部小节。本局没有的区从样本骨架删除并重排，不留空位。
3. 为每个用户可见区域定义 block、位置、显示名和渲染方式。模型生成区读取对应 block；程序投影区直接绑定权威数据。
4. 隐藏 `state_ops` 等维护区列入非渲染处理，不创建 DOM 节点。
5. 写完整 HTML/CSS/JS，创作时一次生成并固定；游玩只灌数据，不再重写前端。美化用配色、字体层级、边框、间距，以及 CSS 或简单内联 SVG，按本次能写稳的程度完成。JS 通过 `present.onData(render)` 接收数据；地图所需的 SVG 从拓扑数据绘制，游玩模型不输出 SVG。
6. 给一份非正史 `present.v1` 预览数据，覆盖所有可见区域与空态。

模板总量不超过 60 KB。材料足够便直接成稿；会改变阅读结构的缺口交给 `self_score.gap`。产物正文不放评分、诊断、追问或开放问题。
```

## principles

```principles
1. 语义区域必须全部有去处；未启用区域不补齐，隐藏维护区不渲染。
2. 正文是主阅读面。辅助状态、线索、地图和文字选项按用途确定层级，不平均分割注意力。
3. 程序投影区只消费权威 block：变量、拓扑和程序结果不要求模型重复填写。
4. HTML 只放稳定骨架；数据由 `present.onData` 注入。缺 block 时按合同省略或显示空态。
5. Tab、折叠、缩放等纯本地交互可以使用；不得联网、提交表单、弹窗、顶层导航或向宿主发送用户行动。
6. Markdown 使用宿主提供的安全渲染能力；动态文字使用安全 API 或转义后写入，不能拼接未清洗 HTML。
7. 地图/关系图由 JS 根据结构化拓扑绘制；显示坐标只属于布局，不回写世界真相。
8. 预览只用于验收前端，不写成开场白或正史。
9. 美化落在配色、字体层级、边框、间距和简单内联 SVG 上，写进 CSS，按本次能写稳的程度完成。
```

## probe

```probe
每轮 1～2 点。优先确认阅读主面、辅助区域是否需要并列或折叠、拓扑采用何种可读形式。语义内容、篇幅、变量更新规则不在这里重议。
```

硬规则：
1. 输出合法 JSON；`数据契约.blocks` 必须覆盖回复呈现的全部用户可见区域，id 保持一致。
2. 程序投影区不得改成模型生成；隐藏维护区只能进入 `不渲染`，不得出现在 DOM 或预览 blocks。
3. `frontend.html/css/js` 均须给出可执行内容；合计不超过 60 KB。JS 必须调用 `present.onData(render)`。
4. HTML 不嵌入本轮数据；动态文字安全渲染。禁止网络、表单、弹窗、顶层导航和宿主行动回传。

6. `示例灌数` 是非正史预览，schema 固定 `present.v1`，只含用户可见 blocks。
7. 不重定义语义区域、篇幅、文风、变量规则、随机数或 0 层槽位更新。
8. 产物正文不含自评、追问或开放问题。
9. `mount` 固定为 `["world-simulator", "narrator"]`；兼容旧称 tag `设计.回复格式`。

## score

```score
区域落实：
- 5：每个可见语义区域都有 block、落点和渲染器；隐藏区明确不渲染。
- 3：主体完整，但有一个辅助区落点或空态含糊。
- 1：漏区，或擅自添加回复呈现没有的内容。

阅读结构：
- 5：正文始终是主阅读面，辅助信息层级与响应式布局服务本局体验。
- 3：总体可读，但某个并列区略抢正文或窄屏处理不足。
- 1：区域平均堆叠，阅读焦点混乱。

权威绑定：
- 5：变量、拓扑和程序结果只读权威投影，模型生成区边界清楚。
- 3：主要绑定正确，但有一个权威字段仍可能被模型重复填写。
- 1：地图或状态每轮由模型重编。

实现完整：
- 5：HTML/CSS/JS 与 present.v1 合同闭合，空态、安全渲染和故障降级均可实现。
- 3：主体可运行，但有一处事件、空态或数据类型未闭合。
- 1：只有外观描述或空代码，无法执行。

本局化：
- 5：参考壳的方法被消化成本局布局，没有固定产品换皮感。
- 3：适配基本成立，但仍明显照搬单一参考。
- 1：只选一个壳名，没有根据语义区域设计。
```


## examples

```examples
- 只有正文：生成克制的阅读模板，body 用安全 Markdown 渲染，不添加无用侧栏。
- 正文 + 状态：状态 block 绑定程序投影，可放正文上方或紧凑侧区；正文模型不输出状态副本。
- 正文 + 地图：JS 根据 topology block 绘制 SVG；节点名称安全转义，窄屏可切到列表降级。
- 多个辅助区：确有必要时使用本地 Tab；切换只改变当前气泡显示，不向宿主发送消息。
- 武侠阅读：纸色、墨色、细线框和一条简单 SVG 纹样；只保留本局启用的区。
- 不合适：把隐藏 state_ops 做成折叠面板；只写“机械风界面”却不给代码；让模型每轮输出地图 SVG。
```
