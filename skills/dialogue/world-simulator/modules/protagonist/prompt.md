# 主角设定

## meta

```meta
name: 主角设定
id: protagonist
artifact: 设计.主角设定
declaration: >
  保存本局用户所扮演角色的身份名片，以及核心体验和已授权代演真正需要的最少信息。
when: |
  用户代入一个有独立身份、背景、关系或特殊能力的角色，且这些信息会影响核心体验或世界反应。
  LLM 获得较多推进权，而现有材料不足以稳定代演该角色时也使用。
when_not: |
  旁观、无固定主角或纯作者视角时不使用。刻意无名的自我投射不因缺名字而强制使用。
  NPC 有多份或需要统一字段时归生成规则，要留下的单条再写具体实例；世界硬法则归世界法则；第一幕归开场白。
boundary: |
  本能力只交用户角色名片和必要行为依据。体验与权限来自美学纲领，输入及推进方式来自故事推进与交互范式，本步据此控制详略。
feeds: gm
```

## opening

```opening
说说这局里的“你”是谁。名字可以留作 `@玩家`；重点写会影响核心体验或世界反应的身份、背景、关系和特殊能力。只有需要 LLM 多代演时，才补性格与默认反应。
```

## task

```task
把用户材料整理为本局用户角色名片，写入 `设计.主角设定`。先保留承载体验的身份、关系和此人能做的那一件，再按故事推进与交互范式里的代写权限决定要不要行为依据。

`特殊设定` 只写这张名片上的能力或身份。拓扑图谱或世界法则里已有的档位、百分比、价目和阶段链不抄进来，作用里点图名或机制名即可。用户自己扮演时，身份背景够用即可，不替用户设计人格与选择。产物正文不放评分、追问或诊断。
```

## principles

```principles
1. 只设计用户已明确给出、核心体验依赖或运行确实需要的内容。
2. 一张脸测试：逐句问「删掉这句，玩家还知道自己是谁吗？」删了仍知道的句子不落盘。
3. “首富之子”“唯我独法”等若是核心体验成立条件，属于必要设定，不算过度设计。
4. 特殊设定写此人能做什么，限制写做不到什么。档位、百分比、价目、阶段链已在拓扑图谱或世界法则里时，作用只点图名或机制名。作用与设定是同一句时省略作用。
5. `称呼` 可写固定名字，也可写 `@玩家` 表示刻意留白；不要因无名阻塞成卡。
6. 身份与背景一两句；用户没给就写「未定」或省略，不代编来历。
7. 行为依据随推进权增减：用户控制越多越简；LLM 代演越多越具体。
8. 本能力只写各开场共通的玩家角色。不同开场白里玩家身份、处境不同的部分，由开场白写在自己的 `meta.用户角色`，程序会同步成 `设计.主角设定#场景短码`；本能力不为各开场另写 `设计.主角设定#短码`。
9. 不写 NPC 名片、世界百科、文风规则或开场事件。
```

硬规则：
1. 输出合法 JSON；`行为依据` 不需要时整项省略。
2. 不写产物内自评、追问、开放问题或完备度。
3. 不把核心体验所依赖的身份、能力或关系误删为“过度设计”。
4. 不替用户补未授权的人格、目标、情绪和关键决定。
5. `特殊设定` 不复制拓扑图谱或世界法则里的档位表、百分比、价目和阶段链。

## score

```score
宽松度：
- 5：只设计本局运行确实需要、核心体验依赖或用户已明确给出的部分；用户控制越多，留白越充分。
- 3：有少量未经确认、也非体验承重的性格或行为倾向，可能影响用户扮演但容易改写。
- 1：大量替用户设计人格、目标、情绪或行动逻辑，明显挤占用户控制权。

必要度：
- 5：核心体验所需的身份、能力、关系完整；代演信息量与 LLM 获得的推进权匹配。
- 3：缺一项会削弱核心体验或导致代演漂移的信息。
- 1：漏掉“我是谁、我凭什么获得该体验”的承重设定，或 LLM 需要代演却没有行为依据。
```

## checklist

```checklist
- [ ] 核心体验依赖的身份、能力和关系都已保留？
- [ ] 非必要、未经确认的性格与行为设计已删除？
- [ ] 行为依据的详细度与 LLM 推进权匹配？
- [ ] 称呼允许固定名字或 `@玩家` 留白？
- [ ] 特殊设定没有抄机制里的档位、百分比或价目？
```

## examples

```examples
- 好：称呼「林晚」；身份与背景一句穿来当日的处境；特殊设定「能看见别人对她的好感数字」，限制「别人看不见」。
- 好：复制能力的作用只写「接触后可复制对方一项能力」，五档百分比留在拓扑图谱，这里点图名。

偏了就改回：
- 作用写成 1%–100% 的五档表 → 删表，作用留一句能做什么，或与设定同义则省略。
- 把侯府地理、朝堂势力写进背景 → 收到舞台或开场白。
- 为宿舍开场和天台开场各写一张 `设计.主角设定#短码` → 各开场不同的处境写进对应开场白的 `meta.用户角色`。
```
