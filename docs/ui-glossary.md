# 用户可见文案与术语对照（UI Glossary）

**用途**：凡出现在 Web 界面、导出 Markdown、状态 pill、气泡标题、询问卡、检查器上的文案，**禁止直接暴露**内部英文 id（如 `design-core`、`design`、`play`）。内部协议、SKILL 路径、黑板 tag、API 字段仍用英文 id。

**实现**：`src/server/display-labels.ts`（权威映射）；`web/display-labels.js` 须与本文及该文件保持一致。新增高频 id 时：**先改本文 → 再改代码**。

**产品口径**：用户侧与作者文档统一用**业界编排用语的中文译名**——**进料方式 / 配方 / 编排器 / 技能 / 工作流计划 / 运行规格 / 执行单元**。旧拍摄词「导演 / 剧本 / 演员 / 能力」与「总管 / 能力包」仅作历史别称；「世界模拟器」「Boss直聘」不作进料方式名。勿再写进新文案。

文档写法：**中文为主**；英文业界叫法仅在术语表首次定义时括注，正文尽量不再夹英文。

## 0. 核心术语（首选）

| 中文（首选） | 业界叫法 | 用户可见含义 | 内部对应 | 旧称（勿再用） |
|--------------|----------|--------------|----------|----------------|
| **进料方式** | Creation intake | 新建作品**先选**的进料路径：工序编排或对话落盘；决定后面用哪一套配方目录 | `creationMode`：`recipe` / `dictate` | Worker 式、Boss直聘、转述进料（作模式名时） |
| **配方** | Recipe | 进料方式之下**再选一次**的方法起点（如回合推演、快穿短局）；给出建议的近期步骤，可按现场调味 | `recipes/` → 黑板 `创作.选用配方` | 导演（选型）、能力包、第二层「配方」选型 |
| **编排器** | Orchestrator / Supervisor | 会话里负责调度的 Agent：决定下一步调谁、是否追问或结束 | Main Agent / `orchestrator.md` | 导演（调度）、总管 |
| **技能** | Skill / Capability module | 共用工序模块（美学纲领与交互范式…）；编排器从池里选型编排 | `modules/` | 能力、组件池（作者文档可写模块） |
| **工作流计划** | Workflow Plan / Horizon DAG | 本局谈成的**近期**增量有向无环图（步骤 = 技能实例）；可追加、拆分、复用、修订 | `设计.创作流程` | 剧本（流程部分）、死板流程卡 |
| **运行规格** | Runtime Spec / Definition | 可复用的执行声明：执行单元、表、常驻上下文、权限与验收点 | `设计.worker集` 等 | 剧本（规格部分）、Worker 集（对用户） |
| **执行单元** | Worker | 上场执行的一次单元（一次 `run_worker`） | Worker / design-* / play workers | 演员 |

关系口诀：

```text
用户先选【进料方式】（工序编排 / 对话落盘）
        │
        ▼
再选【配方】（回合推演、快穿短局、扩写助手 …）
        │
        ▼
【编排器】调度 → 从【技能】里编排（或对话落盘直接整理产物）
        → 谈成【工作流计划】（工序编排）或落盘产物（对话落盘）
        → 收成【运行规格】
        │
        ▼
【执行单元】按规格上场 → 游玩 / 成稿（运行实例）
```

**两层、各选一次**：新建作品先选**进料方式**，再选该方式下的**配方**。不要叠「能力包 + 配方」，也不要把进料方式叫成某个配方的名字。

**调味**：配方给出的建议步骤是**近期起点**（horizon）；编排时可增量追加、可反复调用标了可反复的技能（每次=彻底新建）。已完成节点要改：在图上点该节点重进（继承旧产物），不必整局重开。验收的是本局【工作流计划】与【运行规格】，不是磁盘上的静态菜谱。

**剧本拆分**：旧称「剧本」同时罩住流程与规格，易混。现固定拆成：
- **工作流计划** = 怎么排技能步骤（DAG）
- **运行规格** = 游玩期按什么声明执行

## 0.1 进料方式与配方对照

新建作品对话框：**进料方式 → 配方 → 名称**。两套配方目录互不共享。内部协议仍用 `recipe` / `dictate`；界面、欢迎语、气泡标题用下表中文。

| 内部 `creationMode` | 用户可见 | 做什么 | 旧称（勿再写进新文案） |
|---------------------|----------|--------|------------------------|
| `recipe` | **工序编排** | 排出工作流计划，按节点逐步验收技能产物。适合要搭可扩展世界、长线规格 | Worker 式、工序图；曾被误称为「世界模拟器」 |
| `dictate` | **对话落盘** | 对话整理进产物；变量/映射用工具钉死；不种节点图。适合快速开玩 | Boss直聘、Boss 直聘、转述进料（作模式名时；「转述」易与叙事转述混淆） |

作者文档可写「节点流程 / `recipes/转述/`」作目录路径，但用户主路径禁止用「Boss直聘」「世界模拟器」称呼这两种进料方式。

常用配方（选项名；内部 id 给机器）：

| 进料方式 | 配方（用户可见） | 内部 id | 定位 |
|----------|------------------|---------|------|
| 工序编排 | **回合推演** | `world-simulator` | 回合互动、可扩展的世界推进与角色扮演；舞台/机制/真值都可以往外长。旧称：世界模拟器（仅配方旧名，不是进料方式） |
| 工序编排 | **扩写助手** | `expand-assistant` | 大纲/分段写作、写手统筹 |
| 对话落盘 | **快穿短局** | `快穿短局` | 围着**一个**核心设定快速代入；难扩展、不适合长期经营；至多简单数值；常带一张主角名片 |
| 对话落盘 | **数据化跑团体验** | `数据化跑团体验` | AIRP / 交互式小说；设定可比短局完整，可选跨轮真值与分档映射 |
| 对话落盘 | **交互式长文生成器** | `交互式长文生成器` | 多轮钉需求与文风，连贯长文/章段（无数值跑团） |
| 对话落盘 | **文本生成器** | `文本生成器` | 创作收范例与模仿面；开玩后主世界出正文、转述出文风 |
| 对话落盘 | **正文组成** | `正文组成` | 只钉呈现格式（壳与分区） |

**回合推演 vs 快穿短局**：前者为可经营的世界留工序；后者故意收成一核短局，不帮用户搭可扩张世界。用户要铺多区域舞台、生成规则、长期势力 → 用回合推演或数据化跑团体验，不要用快穿短局硬撑。

## 1. 原则

1. **内外分离**：id 给机器；中文给用户。
2. **本节词优先**：对用户与作者文档优先用 §0；技术实现注释可写「编排器（Main Agent）」「配方（recipe）」对照。
3. **阶段用产品词**：lifecycle 的 `design` / `play` 用户侧统一为 **创作** / **游玩**（勿译成「设计模式 / 播放」）。
4. **与 SKILL `name` 对齐**：磁盘 worker 若已有中文 `name`，展示优先用 name；本表是缺省与高频兜底。
5. **气泡标题形态**：`{中文名}` 或 `{中文名} · {动作}`，例如「创作 · 流程编排 · 产出」，不要「Worker · design-flow 产出」。

## 5. 游玩期常用执行单元（缺省）

声明里可覆盖；无中文名时用下表：

| 内部 id | 用户可见 |
|---------|----------|
| `narrator` | **叙事转述** |
| `role-decide` | **角色决策** |
| `world-simulator` | **主世界层**（旧称：世界推演） |
| `auditor` | **旁观维护**（表/规则检查；默认空操作） |
| `chance` | **机遇裁定**（主世界层 harness 批量工具；非每轮独立 LLM） |
| `round-present` | **回合呈现** |

配方选项展示名示例：`world-simulator`（recipe）→ **回合推演**（旧称世界模拟器）；`快穿短局` → **快穿短局**；`expand-assistant` → **扩写助手**。

**创造执行单元时**：规格里另写 `name`（中文展示名）。`ref` 仍用英文 kebab；UI 优先 `name`。

### 5.1 游玩拓扑称呼（作者文档）

内部调度单位仍叫 **执行单元（Worker）**——一次上场调用，这个词准确，**不要废除**。

作者讨论职责时可用与酒馆主 GM 同构的说法（对用户 UI 仍用上表）：

| 作者可用 | 典型 ref | 含义 |
|----------|----------|------|
| **旁观维护** | `auditor` | 副 LLM：表/规则检查与按需补充；默认每轮上场、多数轮空操作；不写真相 |
| **主世界层** | `world-simulator` | 读变量与 Progressive 投影、按规则改真值/交事件；多数世界观与查表归这里 |
| **叙事转述** | `narrator` | 把裁决写成用户可见正文（若规格拆了呈现） |
| **机遇裁定** | `chance` | 主世界层 harness 内批量程序工具（掷骰/比点/抽签）；`play_slots.chance` 为 false 时关闭；结果可写入 `运行.本轮.机遇`；非每轮独立上场 |
| **角色视角** | `role-decide` | 仅强信息隔离；只出反应建议 |

推荐调度：`gm → perspective? → narrator → auditor`。

默认少拆：百科、分档性格、章大纲投影 → 主世界层 + 表副作用，**不要**再拆「世界观执行单元」「性格执行单元」。详见 `docs/progressive-data-design.md` §5。

## 7. 等待态 / 焦点（对用户）

| `waitingReason.kind` | 状态摘要（短） | 焦点动作 / 底栏主按钮 |
|----------------------|----------------|----------|
| `intake` | 描述需求 | 发送 |
| `input` | 补充说明 | 发送 / 补充并发送 |
| `worker_questions` | 答题 | 补充并发送；已进技能步时旁挂「返回节点」 |
| `approve_step` | 确认 | 同意并开始；重进已完成节点时文案为「回头修改 · {技能名}」；次要为「返回节点」 |
| `pick_creation_step` | 选节点 | 点图上可进入的节点即开始；要看技能池点上方「技能」；要改排在底栏写意见再发 |
| `review_artifact` | 视产物（勿一律「验收」） | **流程编排** → 确认编排；技能步 → 接受；开场 → 选定此开场。旁挂「按意见改编排 / 按意见修改」 |
| `next_intent` | 说话 | 继续（可留空） |
| `revision` | 说话 | 按意见修改 |

**返回节点**：已点进某步（尤其可增殖原型刚增殖出的实例）但还没写完时，退回分层图。未验收的空实例从图上撤掉，避免误点留下一条空槽。已完成节点重进后返回则保留该节点。勿写成「取消作品」或浏览器后退。

## 8. 禁止出现在用户主路径上的写法

- `Worker · design-core`、`run_worker(design-core)`
- 顶栏 / pill 写 `design` / `play` 英文
- 「总管会调度 design-core」「导演会先谈剧本」（应写「编排器会先谈工作流计划」或「将开始：创作 · 流程编排」）
- 新建作品同时出现「导演 + 配方」或「能力包 + 配方」两层选择
- 询问卡标题直接写 `design-core`
- 新文案继续使用拍摄词「导演 / 剧本 / 演员 / 能力」作首选
- 用「世界模拟器」「Boss直聘 / Boss 直聘」称呼进料方式；用「Worker 式」作用户可见进料名

技术日志、导出里的「调试附录」、开发者文档不受本条限制，但默认导出给用户的 Markdown 应走同一套映射。
